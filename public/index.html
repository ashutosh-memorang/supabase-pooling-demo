ConnectionWhat your program opens to the pooler. Closing it does not close the database process behind it.
Login roleThe database user (test_app, test_delivery). A backend is logged in as one role for its whole life.
PoolSupavisor keeps a set of backends per role + mode. In transaction mode, each transaction borrows whichever backend is free.
Backend PIDpg_backend_pid() — the ID of the real Postgres process. Same PID = same process = same leftover settings.

Realistic test · app, hub and assessment keep writing while a migration runs

Tables learners, assessments, submissions, hub_events in schema realistic_test (fake data). Six service connections (2 each for app, hub, assessment) write for 30 s through one shared login test_shared on the transaction pooler, like your single connection string. At 6 s a migration adds a column, backfills, then runs a "verification" step that does a session-level SET default_transaction_read_only = on and disconnects.

Run 1: the migration uses the same shared login → expected BLOCKED (some writes fail, which ones is luck). Run 2: the migration uses its own login test_migrator → expected NOT BLOCKED.
